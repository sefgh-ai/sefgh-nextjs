PROMPT:
"Create a nested boxes diagram showing the React Context Provider hierarchy:
- Title: 'Critical Provider Ordering in app/layout.js'

- Nested structure (like Russian dolls):

OUTERMOST BOX - ThemeProvider (dark purple, largest):
- Label: '1. ThemeProvider' with theme icon (sun/moon)
- Purpose: 'Manages dark/light mode, injects CSS variables'
- Provides: theme, setTheme
- Must be first: 'Enables theme detection before any rendering'
- Border: Thick, glowing purple

  SECOND BOX - AuthProvider (blue):
  - Label: '2. AuthProvider' with lock icon
  - Purpose: 'Manages authentication state, JWT tokens'
  - Provides: user, loading, signOut, refreshUser
  - Depends on: Theme (for auth UI)
  - Listens to: Supabase auth state changes
  - Border: Solid blue with shield icon

    THIRD BOX - SettingsProvider (green):
    - Label: '3. SettingsProvider' with gear icon
    - Purpose: 'Controls settings modal visibility'
    - Provides: isSettingsOpen, openSettings, closeSettings
    - Depends on: Auth (user preferences)
    - Border: Solid green

      FOURTH BOX - LanguageProvider (orange):
      - Label: '4. LanguageProvider' with globe icon
      - Purpose: 'Internationalization, language switching'
      - Provides: t (translate function), locale, changeLanguage
      - Depends on: Auth (user language preference)
      - Border: Solid orange with language flags

        INNERMOST - PageWrapper/Children (white):
        - Label: 'Page Content' with document icon
        - All providers available via hooks:
          * useTheme() → theme, setTheme
          * useAuth() → user, loading, signOut
          * useSettings() → isSettingsOpen, openSettings
          * useLanguage() → t, locale, changeLanguage
        - Border: White with content icon

- Right side panel: CODE EXAMPLE
```jsx
// src/app/layout.js
export default function RootLayout({ children }) {
  return (
    <html suppressHydrationWarning>
      <body>
        <ThemeProvider>
          <AuthProvider>
            <SettingsProvider>
              <LanguageProvider>
                <PageWrapper>
                  {children}
                </PageWrapper>
              </LanguageProvider>
            </SettingsProvider>
          </AuthProvider>
        </ThemeProvider>
      </body>
    </html>
  );
}
```

- Bottom section: DEPENDENCY FLOW
- Arrow diagram showing data flow:
  Theme → Auth → Settings → Language → Page
  'Each provider can access providers above it'
  'Providers cannot access providers below'

- Warning box (red border):
  ⚠️ 'CRITICAL: Do not reorder providers!'
  'Changing order will break dependencies and cause runtime errors'
  Examples:
  ✗ Auth before Theme → Auth UI won't have theme
  ✗ Language before Auth → User preference won't load

- Side annotations showing hook usage in components:
  Component.jsx:
  ```jsx
  'use client';
  import { useAuth } from '@/contexts/AuthContext';
  import { useLanguage } from '@/contexts/LanguageContext';
  
  export default function Component() {
    const { user } = useAuth();
    const { t } = useLanguage();
    return <div>{t('welcome', { name: user.name })}</div>;
  }
  ```

- Performance note:
  'Context updates only re-render subscribed components'
  'Use multiple contexts instead of one large context'
  'Memoize context values to prevent unnecessary renders'
